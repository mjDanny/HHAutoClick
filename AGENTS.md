# Development Rules

This project is intended to be maintained as a public, professional personal repository.

## Workflow

- Work in small, reviewable iterations.
- Commit after logically complete small steps.
- Avoid large "everything" commits.
- Prefer clear architecture boundaries between domain logic, infrastructure, and UI.

## Required Checks

Run these before every commit:

```bash
./venv/bin/python -m ruff check .
./venv/bin/python -m pytest
./venv/bin/python -m mypy app tests
```

## Git Discipline

- Use Conventional Commits:
  - `feat: ...`
  - `fix: ...`
  - `docs: ...`
  - `test: ...`
  - `refactor: ...`
  - `chore: ...`
- Do not use branch names, commit messages, documentation, or README text containing:
  - `codex`
  - `chatgpt`
  - `ai-generated`
  - `generated by AI`
  - `openai-generated`
  - `bot-made`
  - similar markers implying the repository was machine-generated.

## Security

- Never commit secrets, tokens, cookies, browser state, `.env`, `.local`, database files, or real user data.
- Keep example configuration files free of real tokens and private credentials.
- Browser profile data must stay local and ignored by git.

## Safety Boundaries

- Do not implement CAPTCHA bypass, anti-detect browser behavior, proxy rotation for stealth, fingerprint spoofing, or hidden automation.
- Do not automatically complete employer tests or submit answers without explicit user confirmation.
- `AUTO_APPLY_ENABLED=false` and `DRY_RUN=true` must remain the default settings.
